## 建议实现范围

推荐分两步交付，保持最终 OA 弹窗选数目标：先实现平台查询引擎与物料任务配置，再接入客户 OA 控件并联调。另一种选择是等待 SDK 和测试环境齐备后一次完成两侧；可以减少中间适配，但会推迟平台侧开发。

平台侧放在 `bl-integration/reference`，管理员接口按既有习惯放在 `bl-admin`；复用独立 U8 SQL Server 数据源。按用户后续澄清，SQL 全部结果字段通过通用接口返回，元数据和查询能力需要前台配置页；OA 回填关系通过 OA 前台配置。SQL 可保持受控资源，元数据不能仅由代码文件维护。真实 taskCode 待命名，不能从空的旧任务编号或浏览器地址推定。

查询接口接收受控筛选字段、筛选值与分页信息，返回字段元数据和数据行。编码/名称/规格作为首批筛选候选，具体范围依据旧字段配置和 SQL 确认。分页需要稳定排序及明确唯一标识；参数化查询，限制页大小和执行时间。未知任务、非法筛选、数据源未启用和查询失败应分别给出明确错误，不能把数据库不可用表现为空列表。该同步查询不调用 PushPipeline，也不创建人工重试任务。

OA 侧按实际 SDK 开发参照控件/适配：提取筛选参数，调用平台查询，在当前表单或明细行回填经配置的字段。集中管理平台地址与服务间凭据，凭据不得发送到浏览器。只读查询错误不清空现有表单字段；取消选择不修改数据。真实部署前核实调用用户、表单和任务的授权边界。

验收应覆盖：筛选与分页正确、SQL 注入输入被参数化处理、非法字段/排序被拒绝、字段别名一致、无数据与连接失败区分、重复编码处理，以及同一测试数据下旧 DEE 与新平台结果对照。OA 联调另核对当前明细行回填、取消、超时和用户权限。替身测试通过不能登记为 U8 查询或 OA 回填通过。

2. **实际字段回填属于实施配置**：运行截图已确认明细行单选、编码/名称/规格三项筛选、六列列表和每页 200 条。平台和插件应提供通用前台配置能力，具体表单映射/匹配方式不作为平台开工阻塞项；OA 联调时再使用真实配置验收。
3. **后续真实联调输入**：U8 只读测试连接和 SQL Server 版本、少量脱敏完整结果；OA 具体补丁、SDK/样例控件、扩展部署权限。用户已告知测试环境仍在准备，不重复要求现在完成。
