# 物料参照：平台与 OA 插件对接说明

日期：2026-09-07。性质：供平台开发、OA 插件开发和业务验收共同对齐的契约草案；接口尚未实现、未部署。

> 正式同步开发请使用 [参照接口 V1.0 文档包](api/reference-v1/README.md)，其中包含 OpenAPI 和模拟样例。本文保留前期分工与研究记录；HTTP 协议以 V1.0 为准。

> 实施更新：平台业务源码已完成本地验证，尚未部署及真实联调；见 [实现与环境交接](reference-v1-implementation.md)。

> 用户澄清：每条参照返回其 SQL 查询的全部字段，显示/筛选及元数据映射由前台配置驱动。通用插件应提供元数据接入与配置能力，不为每张表单编写或硬编码回填映射。具体业务字段配置不作为平台开工门槛。

## 基线与目标

遵循项目基线 5.1、5.2.2、6、7、8、9 节：一套 ReferenceEngine，通过任务配置迁移各类参照；OA 独立控件/扩展调用平台实时查询 U8，负责展示和回填。平台与插件通过 HTTP 解耦，平台不依赖 A8 SDK，插件不依赖 Spring Boot 3 或 bl-integration。

本次首条任务为采购请购单明细行的物料参照：点击存货编码，搜索、分页、单选，确定后回填当前行。先做参照是用户批准的开发顺序调整，架构不变。默认生产部门字段统一为 `mrscbm`；此前冲突记录属于助手识图错误。

## 分工

| 项目 | 数据交换平台 | OA 插件（用户同事） |
| --- | --- | --- |
| 任务定义 | taskCode、数据源引用、SQL 资源、可在前台维护的元数据、过滤与排序白名单 | 前台选择任务/结果集、绑定控件 |
| U8 查询 | SQL Server 连接、参数化查询、分页、结果字段与错误 | 不直接连接 U8，不保存 SQL 和 U8 账号 |
| 界面交互 | 元数据配置页、任务/结果集描述、完整字段的分页数据 | 接入元数据以配置显示列、筛选与字段关联；运行时按配置提供选数回填 |
| 数据转换 | 保留和执行原 SQL 的业务规则 | 将返回字段绑定并回填 OA 控件，不重算单位/库存等业务规则 |
| 认证 | 验证专用服务身份、允许调用的任务及受控参数 | OA 登录/表单权限校验；服务端保管凭据并调用平台 |
| 定位问题 | 执行/阶段记录、耗时和关联标识 | 网络投递错误、控件错误与相同关联标识 |

“返回字段到 OA 控件”的绑定属于参照界面适配；U8 业务数据转换、物料筛选与换算率计算归平台。不要把全部业务映射放进插件。

## 平台实现方式

每条参照使用任务配置，包含 taskCode、U8 数据源引用、受控 SQL 资源、字段元数据、允许筛选的字段/操作符及分页排序规则。任务元数据及查询能力通过平台前台维护，配置持久化并可追踪；OA 目标字段映射在 OA 前台维护。必要的元数据配置页面不等于完整低代码/ETL 编排，原基线“不必须提供在线 SQL 编辑器”也不等于禁止元数据配置界面。

ReferenceEngine 根据任务配置校验查询、绑定参数、实时读取 U8 并返回结果；仓库/供应商等后续同构参照通过新增配置迁移，不为每条任务复制一套 Java 查询流程。物料原 SQL 的关联、分组、换算率和 dEDate IS NULL 条件保留。

共用既有执行/阶段日志模型，但采用同步查询路径，不调用 PushPipeline 或 SyncPipeline。未保存表单的 masterId 可空。当前 Stage 1 表约束不支持空 masterId，需要在实际开发时做最小增量调整；此次说明没有授权外部部署或执行新 SQL。

## HTTP 开发契约

完整字段约束、请求和响应见 [V1.0 文档](api/reference-v1/README.md) 及 [OpenAPI](api/reference-v1/openapi.json)。旧版 HTTP 示例已移除，避免双方按不同结构实现。

- 基础路径 `/integration/openapi/v1`；包含 `/status`、`/reference/tasks`、`/reference/tasks/{taskCode}/metadata`、`/reference/tasks/{taskCode}/query`。
- 首条 taskCode 为 `U8_MATERIAL_REFERENCE`，resultSetCode 为 `tou`；这是新平台配置，不冒充旧 DEE 任务编号。
- 服务端使用 `X-Integration-Key`；请求关联标识通过 `X-Request-Id` 请求头传递。
- 查询包含 metadataVersion、结构化 filter、sort、分页；操作符使用 values 数组。具体格式及错误码以配套文件为准。
- 允许的筛选字段和操作符来自任务元数据，编码、名称、规格为首条任务初始配置；不传 SQL、whereString 或任意排序表达式。

每行返回该任务 SQL 产生的全部字段，数据行采用通用字段集合。当前物料 SQL 是 14 列：`jz`、`zdwbm`、`fdwbm`、`cInvCode`、`cInvName`、`cInvStd`、`zdw`、`fdw`、`hsl`、`zldj`、`iMassDate`、`chdl`、`cd`、`mrscbm`；14 不是引擎固定字段数。字段类型、空值及数值序列化规则由统一契约与元数据表达，编码始终按字符串保留前导零。前台选择显示六列不影响完整返回；隐藏字段仍可用于配置的回填。全部字段与全部记录不同，记录仍分页。按选中完整结果行及已保存映射回填，不根据 cInvCode 再任选一行。

错误必须区分未认证/无权访问、非法参数、未知任务、数据源未启用、查询超时/连接失败。双方固定 HTTP 状态和业务错误码映射；查询失败不能表现为查询成功且 rows 为空。已到平台的错误保留关联标识，未到平台的失败由插件使用 requestId 定位。

若表单权限或任务规则需要额外上下文，可传可信 formId/操作者信息供校验和日志使用；由 OA 服务端校验/补充，不能直接信任浏览器提交的身份。当前物料 SQL 不以 masterId 为参数，不要求为首次填单伪造主记录 ID。明细行上下文由插件保留，平台无需理解 OA 私有行对象。

## 同事需要反馈的内容

1. **扩展可行性**：实际 A8 补丁/控件前端版本；采用哪个受支持的控件扩展入口；是否已验证按钮、弹窗与回填。无需平台获得完整私有 SDK，但应提供必要的调用约束。
2. **配置能力**：能否让新平台任务/结果集/字段元数据进入 OA 设计配置流程；显示、筛选、回填映射如何通过前台设置并保存。具体表单映射是实施配置与验收样例，不要求业务用户先提供一张硬编码映射表才能开发平台。
3. **行与表单行为**：如何锁定点击所在明细行；未保存表单、连续切换行、取消和超时如何处理；回填后是否有原有计算/校验需要触发。
4. **调用条件**：OA 服务端可访问的平台测试地址、网络/证书要求；可用的服务端 HTTP 调用方式、超时限制。凭据通过安全配置注入，不贴入对接文档。
5. **联调结果**：至少一组脱敏的实际查询请求/响应、同一 requestId 两侧日志和选中后的字段回填截图。确认成功、空结果、无权限、断网/超时均处理正确。

平台需同步提供：接口定义、字段元数据、请求/成功/失败样例、服务身份接入说明、测试地址、联调定位方式和平台测试结果。同事不必先设计一套平台返回格式再让平台反向适配；先共同固定 HTTP 契约。

需同事回答的是扩展入口、元数据注册/读取结构、配置存取方式及查询调用约束。旧 DEE 的原生配置能力应优先保留用户体验，但必须实测其能否通过受支持的扩展接入新平台；不假定仅替换 URL 即可，不让生产调用绕回 DEE 引擎。

## 连接与运行闭环

1. 平台部署到 OA 服务器能够访问的测试地址，并配置 U8 只读数据源；localhost 只能表示调用所在机器，不用开发者电脑的 localhost 作为远程 OA 配置。
2. 分配插件专用的服务身份和允许访问的 taskCode，地址、凭据、超时集中放在 OA 服务端配置。认证采用 V1.0 约定的 X-Integration-Key，不复用管理员个人登录凭据。
3. 同事安装控件，给采购请购单存货编码字段绑定任务，配置返回字段到该明细表字段的映射。
4. 用户点击/筛选/翻页时，OA 插件服务端调用平台；平台校验后实时查 U8，在本次 HTTP 请求中返回数据。平台失败或连接超时则由插件提示，不覆盖表单现有值。
5. 用户单选确定后，插件在当前明细行回填；取消不改值。查询与选择均不向 U8 写单、不触发异步推单，也不要求平台主动回调 OA。
6. 表单后续保存/发送仍走 OA 自身机制。单纯物料选择无需额外“选择成功回执”接口；当前闭环验收由两侧日志与实际字段结果共同证明。如后续另需持久化选择审计，应单独定义，不用查询成功冒充回填成功。

## 联调顺序与验收门槛

1. **协议联调**：先以明确标记的固定测试样例核对插件请求、分页、空值及字段绑定；不计为 U8 查询通过。
2. **真实查询联调**：连接 U8 测试账套，同一筛选条件下核对旧 DEE 与新平台数据、总行数、换算率与同编码多行。
3. **OA 回填联调**：在实际采购请购单选择物料，逐字段核对当前行；验证多行、重新选择、取消与保存后的结果。
4. **故障联调**：覆盖无结果、错误参数、无权调用、平台不可达、U8 超时，确保错误可定位且不清空已有数据。

只有真实 U8 查询与实际 OA 选数回填均验收通过，才将该任务标记为迁移闭环完成。
