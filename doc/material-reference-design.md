# 物料参照实现方案草案

日期：2026-09-07。状态：供用户确认的方案，尚未实施。

> HTTP 开发契约现以 [参照接口 V1.0](api/reference-v1/README.md) 及其 OpenAPI 为准；本文保留架构与实现说明。

> 实施更新：平台业务源码已完成本地验证，当前进展及环境限制见 [首条物料参照实现记录](reference-v1-implementation.md)；下文“尚未实施”等描述保留为前期方案背景。

> 范围修订：用户明确平台应返回该任务 SQL 查询的全部字段，并通过前台配置完成元数据与字段映射。下文以本次修订为准；具体表单的显示列、筛选项和回填目标是配置数据，不是平台开工前必须逐项向业务人员索取的固定需求。

## 目标和交付边界

最终目标：采购请购单当前明细行点击存货编码后，弹出实时物料查询列表，按编码/名称/规格筛选，单选确定后回填到该行。

建议先实现可测试的平台 ReferenceEngine 与物料查询接口，随后在客户 SDK 和测试环境具备后完成 OA 参照控件适配。平台侧完成不能表述为 OA 已替换 DEE。原始 DRP、SQL 与截图作为迁移材料，生产执行链路不调用 DEE。

另一方案是等待 U8/OA 测试环境与 SDK 齐备后一起实现两侧，可以直接验证端到端，但平台开发也会等待。推荐先完成平台侧。

## 平台组件与查询协议

- `bl-integration/reference`：任务定义、元数据、输入校验、参数化查询与分页，一套引擎加载任务配置。SQL 使用受控资源；任务元数据和筛选/排序能力通过平台前台维护并持久化，不能只提供文件配置而缺少用户要求的配置界面。
- `data-platform-ui`：提供参照任务元数据配置页，加载/维护 SQL 结果字段及显示名称、类型、顺序，维护允许筛选的字段/操作符和排序能力，并支持结果预览。OA 具体字段的关联映射通过 OA 前台配置，由通用插件读取和执行。
- `bl-admin`：参照查询控制器，使用若依现有登录和权限边界完成平台内验证，不增加匿名查询入口。OA 服务间身份校验在 OA 适配阶段按实际契约接入，不向浏览器暴露平台凭据。
- 任务建议编号：`U8_MATERIAL_REFERENCE`，为新平台建议值，不是旧 DEE 编号。
- 接口统一采用 [参照接口 V1.0](api/reference-v1/README.md)：基础路径 `/integration/openapi/v1`，包含连接检测、任务目录、元数据、查询四个接口；使用专用服务凭据，插件不使用管理员个人登录令牌。
- 筛选字段与操作符由任务配置定义，引擎支持受控的结构化筛选并在服务端验证。`cInvCode`、`cInvName`、`cInvStd` 是本物料任务的初始配置；包含/前缀/精确等匹配方式是可配置能力，不因更换筛选方式而修改 Java 代码。高级筛选所需的组合条件由双方统一契约表示，不能把任意 whereString 传给数据库。
- 默认每页 200 条，首版最大 200 条，支持页码、总条数和清空筛选。查询值绑定为 JDBC 参数；LIKE 模式中的通配符按文字搜索语义转义，动态字段和操作符只允许配置白名单。
- 接口每行返回该任务 SQL 查询产生的全部字段，不按列表显示列裁剪，也不将当前 14 个物料字段固化为通用引擎 DTO。元数据保留字段标识和业务含义；六个显示列是当前界面配置，改变显示、筛选和回填配置不改变平台完整返回。原数据的空值、前导零与数值精度需保留；默认生产部门统一为用户确认的 `mrscbm`，此前别名冲突判断是助手识图错误，已撤销。
- 使用已有独立 U8 SQL Server 数据源和只读账号。U8 未配置时给出明确“数据源未启用”错误，不生成虚构业务数据、不返回伪装成功的空列表。

## SQL 行为与分页

基于 [DEE 原查询](migration/material-reference/dee-source.sql)制作生产查询资源，保留 JOIN、GROUP BY、HAVING 和换算率计算。移除旧 DEE 条件占位符后，由引擎在外层添加参数化筛选。查询 SQL 从受版本管理的资源读取，不允许从 API 传入 SQL。

按结果行统计总数，保留同编码多行。新分页需要显式排序；建议以编码为主并以其余结果字段补充排序，避免仅按编码排序时多行跨页不稳定。SQL Server 版本未确认前，不将 OFFSET/FETCH 可用性视为既定事实；实现时选择与测试环境兼容的分页方式并验证原字段类型可排序。记录总数与页查询可能在不同时间读取变化中的现存量，不承诺跨请求数据库快照。

设置有上限的查询执行时间。区分非法参数、未知任务、未配置数据源和查询失败；对用户返回可读错误，对技术日志记录任务与错误类型，不向前端输出数据库连接信息或凭据。

## OA 接入

按客户 A8 10.0 SP1 具体补丁和 CAP4 控件前端版本实现参照适配，沿用官方扩展方式，服务端调用平台查询。控件配置任务编号、可用筛选和返回字段到 OA 字段的映射；实际字段名与映射以客户表单定义为准。

单选确定仅回填当前明细行；取消、查询失败、无匹配结果不覆盖现有值。编码/名称/规格/质量等级/主单位等目标字段虽在表单上可见，仍需核对实际配置；采购单位是否取辅单位、是否回填换算率、是否触发数量计算，均不从字段名称推断。默认生产部门字段名已确认是 `mrscbm`，其是否绑定到当前表单按实际字段配置确定。

OA 插件由用户同事负责开发；平台工程不依赖客户私有 SDK。同事负责选择和验证客户版本的控件扩展 API，双方通过 HTTP 契约对齐。协作输入、接口草案与联调验收见 [插件对接说明](material-reference-plugin-handoff.md)。

## 参照记录与既有底座

参照同步查询复用基线中的执行记录/阶段日志模型，记录任务、查询阶段、耗时、成功/失败和可定位标识；不强制继承 PushPipeline，不使用异步推单或整条业务重试。对于首次填单尚无 OA 主记录的场景，masterId 可空，不伪造 ID。

当前 Stage 1 的 `int_execution.master_id` 为 NOT NULL，Push 受理服务也要求 masterId 和推单 Handler。实现参照日志时需最小范围补齐共享模型的可空能力，并保留 Push 自身的必要校验；不能直接把参照请求送进已有 Push 受理入口。这是拟实施内容，不代表本次已修改数据库。

## 验证与验收

平台自动化测试覆盖输入限制、参数化筛选、非法字段拒绝、LIKE 转义、分页边界、重复编码保留、精度/空值/前导零、数据源关闭及失败反馈。原 SQL 的换算率与停用规则以真实 SQL Server 对照验证，不能只凭替身测试确认。

真实 U8 验收使用同一测试账套/数据时点，对照无筛选与三类筛选的总行数和完整字段，并检查换算率分支及同编码多行。OA 验收覆盖字段点击、单选、当前明细行回填、取消、超时、权限和多行场景。全部通过后才登记物料参照迁移闭环完成。

## 后续需要的客户资料

完整来源 SQL 与运行界面已收到，不再重复索取。返回字段、匹配方式和 OA 字段映射不再列为平台通用开发的前置阻塞项，它们分别由 SQL、任务元数据配置和 OA 前台配置驱动。平台侧可以启动设计与开发；平台开发方负责提出通用契约并与插件同事技术对齐。真实联调仍需要 U8 只读测试连接和 SQL Server 版本，并由同事验证客户补丁下元数据接入、前台映射、明细行回填与部署。旧 DEE 内置注册项能配置元数据，不代表它无需适配就支持新的 Reference API。
