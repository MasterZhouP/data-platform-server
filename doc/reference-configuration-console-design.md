# 参照 SQL 与数据源配置控制台设计

日期：2026-09-14
状态：设计待最终评审，尚未实施

## 1. 背景

当前平台已经具备参照任务元数据维护、字段检查、分页查询预览，以及销售出库单读取和推送能力，但配置职责分散：

- 参照 SQL 以 `integration/reference/*.sql` 的 classpath 资源随应用部署，前端只能选择已部署文件，不能形成草稿、验证、发布和回滚闭环。
- OA、U8 数据源由 `application.yml` 和环境变量在应用启动时创建，运行中无法安全修改或切换。
- 参照任务页面将字段配置和查询预览放在大弹窗中，SQL、数据源、字段和发布状态之间缺少清晰关系。
- 销售出库页面在查询成功后已有较完整的单据内容，但空状态和失败状态缺少数据源、SQL 版本、目标系统及最近执行等运行上下文。
- 数据库异常会以接近原始技术异常的形式出现在页面，不适合作为最终运维界面。

本设计把数据源、参照 SQL、字段元数据和预览能力统一成轻量配置控制台。它不是完整 ETL 或低代码编排平台，不引入拖拽流程和任意脚本执行。

## 2. 目标与非目标

### 2.1 目标

1. 管理员可以在平台中维护参照业务使用的数据源，并在不重启应用的情况下测试和启用新配置。
2. 参照 SQL 支持草稿、只读安全校验、字段检查、原始结果预览、业务效果预览、发布和回滚。
3. 生产查询始终使用一个明确的已发布 SQL 版本；编辑草稿不能影响正在运行的业务。
4. 页面能够直接说明任务是否具备运行条件，并提供从错误到诊断入口的闭环。
5. 数据源密码、完整连接串和敏感数据库异常不返回浏览器、不进入普通审计日志。
6. 保留现有参照接口契约、结构化筛选、字段完整返回和执行日志能力。

### 2.2 非目标

- 不在本阶段提供跨节点流程编排、可视化 JOIN、字段转换脚本或通用 ETL 设计器。
- 不允许浏览器直接连接数据库。
- 不允许前端向执行接口提交任意 `WHERE` 字符串或未持久化的临时 SQL。
- 不把 OA 表单字段映射迁入平台；该映射继续由 OA 插件和 OA 前台负责。
- 不把生产数据库账号升级为写账号；所有参照数据源必须使用数据库侧只读账号。

## 3. 核心设计原则

### 3.1 管理界面与执行边界分离

浏览器只调用管理 API。所有 SQL 校验、数据源连接、预览和生产查询都在后端完成。前端永远不会获得可直接连接数据库的完整信息。

### 3.2 草稿与已发布版本分离

SQL 编辑产生草稿版本。字段检查和预览针对持久化草稿运行，生产任务只读取已发布版本。发布是一次带版本检查的原子切换。

### 3.3 配置状态与运行健康分离

“已启用”表示配置允许被使用；“健康”表示最近一次检测成功。短时连接故障不会自动篡改配置状态，但会更新健康状态并阻止危险操作。

### 3.4 纵深防护

SQL 语法检查、语句类型白名单、数据源只读事务、数据库只读账号、超时、行数限制和权限审计同时生效。任何单层校验都不能作为唯一安全边界。

## 4. 总体架构

```text
管理端浏览器
  ├─ 数据源管理
  ├─ SQL 编辑与版本
  ├─ 字段/查询规则
  └─ 双层预览
          │
          ▼
管理 API ── 权限、版本冲突、脱敏、审计
          │
          ├─ 配置目录服务
          │    ├─ 数据源配置与密文凭据
          │    ├─ SQL 草稿/发布版本
          │    └─ 任务元数据
          │
          ├─ 动态数据源注册表
          │    └─ Hikari 连接池原子切换与旧池回收
          │
          └─ 参照查询引擎
               ├─ SQL 安全校验
               ├─ 字段检查
               ├─ 原始预览
               └─ 业务预览/生产查询
```

生产 Reference API 继续通过任务编码访问。服务端在一次查询开始时固定以下运行快照：

- 任务元数据版本；
- 已发布 SQL 版本；
- 当前活动数据源配置版本。

执行日志记录上述版本标识和 SQL 校验和，不记录密码和完整 SQL 正文。一次请求执行过程中发生新版本发布时，该请求继续使用已取得的旧快照，后续请求使用新版本。

## 5. 数据模型

### 5.1 `int_datasource_config`

保存非敏感连接配置：

| 字段 | 含义 |
| --- | --- |
| `datasource_key` | 稳定唯一键，例如 `u8-prod` |
| `datasource_name` | 页面显示名称 |
| `db_type` | 首期固定为 `SQLSERVER`，模型允许后续扩展 |
| `environment` | `TEST` 或 `PROD` |
| `host`、`port`、`database_name` | 结构化连接信息 |
| `username` | 登录名，读取接口可返回 |
| `connection_options_json` | 加密、证书、应用名等受控选项；不接受任意 JDBC 参数 |
| `read_only` | 必须为 true；后端同时强制只读 |
| `maximum_pool_size`、`connection_timeout_ms` | 有上下限的连接池参数 |
| `status` | `DRAFT`、`ACTIVE`、`DISABLED` |
| `config_version` | 乐观锁和运行快照版本 |
| `last_test_status`、`last_test_at`、`last_test_message` | 最近连接检测摘要 |
| 审计字段 | 创建、修改、发布时间与人员 |

主机、端口和库名属于受限信息，仅授予数据源查看权限的管理员可见；普通任务查看接口只返回数据源名称、环境、启用和健康状态。

### 5.2 `int_datasource_secret`

保存 `datasource_key` 对应的加密密码、密钥版本和更新时间。应用的主加密密钥来自部署环境或外部密钥服务，不存入数据库或代码仓库。

管理 API 只返回 `secretConfigured: true/false`。修改密码使用 `passwordUpdate` 写入字段，响应中不会返回该值。日志、异常和操作记录统一执行凭据脱敏。

### 5.3 `int_reference_sql_version`

| 字段 | 含义 |
| --- | --- |
| `sql_version_id` | 版本主键 |
| `task_code` | 所属参照任务 |
| `version_no` | 面向用户的递增版本号 |
| `status` | `DRAFT`、`VALIDATED`、`PUBLISHED`、`ARCHIVED` |
| `sql_text` | SQL 正文 |
| `parameter_json` | 命名参数、类型、必填和示例值 |
| `checksum` | SQL 与参数定义的校验和 |
| `validation_json` | 语法、安全、数据库编译检查摘要 |
| `schema_snapshot_json` | 字段名、JDBC 类型、可空性等检查快照 |
| `change_note` | 发布说明 |
| 审计字段 | 创建、修改、校验、发布时间与人员 |

同一任务最多保留一个可编辑草稿。发布时将当前发布版本转为 `ARCHIVED`，目标版本转为 `PUBLISHED`，并更新任务指针。历史版本正文保持不可变。

### 5.4 `int_reference_task` 调整

保留现有任务、数据源键和元数据配置，新增：

- `active_sql_version_id`：当前生产版本；
- `config_version`：任务整体乐观锁版本；
- `last_preview_at`、`last_preview_status`：最近业务预览摘要。

现有 `sql_resource` 在迁移期保留为兼容字段。完成数据库版本发布后不再作为主要执行来源，经过一个稳定版本周期后再移除。

### 5.5 执行审计扩展

在现有执行记录的上下文中增加：

- `task_config_version`；
- `sql_version_id` 和 `sql_checksum`；
- `datasource_key` 和 `datasource_config_version`；
- `request_id`；
- 预览类型和结果行数。

不保存查询结果全集。必要的请求参数按现有脱敏与长度限制保存。

## 6. 状态与发布流程

### 6.1 数据源

```text
新建草稿 → 保存 → 测试连接成功 → 启用
   ↑                    │          │
   └──── 修改形成新版本 ┘          └→ 停用
```

启用操作先使用候选配置创建新连接池并执行连接检测。只有新池成功后才原子替换活动池；失败时保留原活动池和配置。旧池停止接收新请求，并在存量请求结束或宽限期到达后关闭。

### 6.2 SQL

```text
创建/修改草稿
  → 静态安全校验
  → 数据库编译与字段检查
  → 原始预览
  → 业务效果预览
  → 填写发布说明
  → 原子发布
```

发布前必须满足：

- 绑定的数据源处于 ACTIVE，最近连接检测成功；
- SQL 安全校验与数据库字段检查成功；
- 字段元数据不存在未处理的删除、重名或类型冲突；
- 至少成功执行一次当前草稿的业务效果预览；
- 当前用户具有发布权限，任务版本未发生并发变化。

回滚不是修改历史版本，而是以历史版本内容生成一个新的已发布版本，因此版本序列和审计记录保持单调、完整。

## 7. SQL 安全与执行规则

### 7.1 允许范围

- 单条 `SELECT`，以及最终产生一个结果集的 CTE 查询；
- SQL Server 标准表、视图、JOIN、GROUP BY、HAVING 和受控函数；
- 由平台定义并绑定的命名参数；
- 结构化筛选、排序和分页继续由 ReferenceEngine 在外层生成。

### 7.2 拒绝范围

- 多语句；
- INSERT、UPDATE、DELETE、MERGE；
- CREATE、ALTER、DROP、TRUNCATE；
- EXEC/EXECUTE、存储过程、动态 SQL；
- SELECT INTO、临时表和跨批次状态；
- 事务控制、权限控制和会话级危险设置；
- 未在数据源允许范围内的服务器、数据库或 schema 访问。

校验由 SQL Server 方言感知的解析器完成，并辅以令牌级兜底检查。解析器无法确认安全时拒绝执行，而不是尝试放行。

### 7.3 数据库侧防护

- 账号只授予必要表/视图的 SELECT 权限；
- JDBC Connection 和事务标记为只读；
- 原始预览默认最多 50 行，不计算全量总数；
- 业务预览和生产查询沿用最大每页 200 行限制；
- 单次查询默认 10 秒，连接检测默认 5 秒；
- 单数据源和单用户均设置预览并发上限；
- 查询取消、超时和连接关闭必须中止数据库 Statement。

### 7.4 参数规则

SQL 参数先在参数配置中声明名称和数据类型，再由后端绑定。参数示例值可用于预览，但不属于发布版本的生产默认值。普通查询接口继续只接收结构化条件，绝不接收任意条件片段。

## 8. 双层预览

### 8.1 原始 SQL 预览

面向配置人员，用于回答“SQL 实际返回了什么”：

- 针对已保存草稿执行；
- 输入命名参数的预览值；
- 返回前 50 行、列标签、JDBC 类型、可空性、耗时和截断提示；
- 保留字符串前导零、空格、NULL 与数值精度；
- 不要求任务启用，不使用生产 Reference API 缓存。

### 8.2 业务效果预览

面向任务配置人员，用于回答“OA 最终会看到什么”：

- 使用草稿 SQL 和当前字段配置的组合快照；
- 支持已声明的筛选条件、AND/OR、排序和分页；
- 显示默认列或全部字段；
- 返回模拟的 Reference API 响应摘要和实际表格；
- 成功结果写入预览审计，但不移动任何定时游标、不创建推送任务。

字段检查发现变更时，页面提供差异：新增字段、删除字段、类型变化和可空性变化。新增字段默认未开放筛选和排序；删除字段必须从默认显示、筛选和排序中显式移除后才能发布。

## 9. 管理 API 设计

接口继续使用若依登录态和权限体系，响应不得包含密码、密文或完整内部异常。

### 9.1 数据源 API

| 方法与路径 | 用途 |
| --- | --- |
| `GET /integration/datasources` | 数据源列表和健康摘要 |
| `POST /integration/datasources` | 新建草稿 |
| `GET /integration/datasources/{key}` | 读取脱敏配置 |
| `PUT /integration/datasources/{key}` | 按配置版本保存草稿，包括可选密码更新 |
| `POST /integration/datasources/{key}/test` | 使用已保存草稿测试连接 |
| `POST /integration/datasources/{key}/activate` | 测试并原子启用 |
| `POST /integration/datasources/{key}/disable` | 停用并检查引用关系 |
| `GET /integration/datasources/{key}/usages` | 查看引用任务 |

被已启用任务引用的数据源不能直接停用。管理员必须先停用引用任务或将任务切换到另一个已启用数据源。

### 9.2 SQL 与任务 API

| 方法与路径 | 用途 |
| --- | --- |
| `GET /integration/reference/tasks/{taskCode}/sql/versions` | 查询版本历史 |
| `POST /integration/reference/tasks/{taskCode}/sql/draft` | 从当前发布版或空模板创建草稿 |
| `PUT /integration/reference/tasks/{taskCode}/sql/draft` | 按版本保存草稿 |
| `POST /integration/reference/tasks/{taskCode}/sql/draft/validate` | 静态安全与数据库编译校验 |
| `POST /integration/reference/tasks/{taskCode}/sql/draft/inspect` | 读取字段并生成差异 |
| `POST /integration/reference/tasks/{taskCode}/sql/draft/preview/raw` | 原始结果预览 |
| `POST /integration/reference/tasks/{taskCode}/sql/draft/preview/business` | 业务效果预览 |
| `POST /integration/reference/tasks/{taskCode}/sql/draft/publish` | 发布草稿 |
| `POST /integration/reference/tasks/{taskCode}/sql/versions/{id}/restore` | 从历史版本生成新发布版 |

现有任务查询和生产预览接口保持兼容。迁移完成后，现有 `inspect` 接口内部改为检查当前发布版本；新配置流程使用明确的草稿接口。

## 10. 权限模型

建议拆分以下权限：

| 权限 | 能力 |
| --- | --- |
| `integration:datasource:list` | 查看数据源摘要 |
| `integration:datasource:view` | 查看脱敏连接配置 |
| `integration:datasource:edit` | 新建和修改草稿、更新密码 |
| `integration:datasource:test` | 测试连接 |
| `integration:datasource:activate` | 启用和停用 |
| `integration:reference:sql:view` | 查看 SQL 和版本 |
| `integration:reference:sql:edit` | 编辑草稿 |
| `integration:reference:sql:preview` | 校验、字段检查和预览 |
| `integration:reference:sql:publish` | 发布和回滚 |

首期不强制不同人员审批，但编辑和发布权限必须可独立分配。所有修改、测试、发布、回滚和停用操作进入操作审计。

## 11. 前端信息架构

“数据交换”菜单调整为：

1. 任务中心；
2. 参照任务；
3. 数据源管理；
4. 执行日志；
5. 定时任务。

### 11.1 参照任务列表

列表字段：任务名称、任务编码、数据源与健康状态、已发布 SQL 版本、草稿状态、字段数量、最近预览、启用状态和更新时间。

操作保持克制：进入配置、业务预览、启用/停用。SQL 发布等高风险操作只出现在任务详情页。

页面顶部显示统计摘要，但不使用装饰性大卡片：任务总数、运行就绪、待发布草稿和异常任务。

### 11.2 参照任务详情

使用独立路由页面，不再使用 94% 宽度弹窗。页面结构：

```text
返回参照任务   物料参照 / U8_MATERIAL_REFERENCE     [草稿] [保存] [发布]
U8 正式库 ●正常  →  SQL v3 ●已验证  →  字段配置 v8 ●一致  →  OA Reference API

[基本信息] [SQL 配置] [字段与查询规则] [数据预览] [版本记录]
```

各页签职责：

- 基本信息：名称、编码、数据源、启用状态、调用方与运行条件；
- SQL 配置：编辑器、参数、校验结果、字段差异和草稿操作；
- 字段与查询规则：显示名称、类型、显示/筛选/排序规则；
- 数据预览：原始预览与业务预览切换；
- 版本记录：发布人、说明、校验和、字段摘要、版本比较和恢复。

离开存在未保存修改的页面时必须确认。保存冲突显示“配置已被其他人更新”，提供重新加载和复制当前内容，不静默覆盖。

### 11.3 数据源管理

列表展示：名称、键、环境、数据库类型、数据库名、状态、健康状态、引用任务数和最近检测时间。

详情页分为基本连接、连接池设置、健康检测和引用任务。密码字段只显示“已配置/未配置”，输入新值后明确提示将替换现有密码。

“测试连接”显示分阶段结果：地址可达、登录成功、数据库可访问、只读验证和总耗时。页面不返回服务器堆栈和完整连接串。

### 11.4 销售出库任务页

保留现有成功预览中的单头、明细、OA Payload 和推送操作。调整首屏：

- 将大面积深色标题区缩成紧凑任务页头；
- 增加一条任务链路状态带：`U8 数据源 → 销售出库读取 → OA 流程`；
- 查询区旁显示数据源、配置版本、定时状态和最近成功执行；
- 空状态展示运行条件与最近五次执行，不留下大面积无信息区域；
- 失败状态显示业务化摘要、错误编号和诊断入口。

例如数据库对象不存在时显示：

> 读取失败：SQL 引用的对象不存在，或当前账号无访问权限。
> 数据源：U8 正式库　错误编号：REF-XXXX
> 操作：检测数据源 / 打开 SQL 配置 / 查看执行日志

完整 SQL 和堆栈只进入受控后端日志。

- `#3A7AFE` 链路蓝：当前步骤和主要操作；
- `#1F8A63` 健康绿：连接、校验和运行成功；
- `#C87A16` 告警琥珀：草稿、待验证和降级；
- `#C94A4A` 故障红：阻断性错误；
- `#F4F6FA` 工作区灰：页面底色。

状态不能只依赖颜色，必须同时包含图标和文本。

### 12.2 字体与布局

- 中文正文优先使用内部可部署的 MiSans；无法统一部署时使用系统中文字体栈；
- SQL 编辑器使用随应用打包的等宽字体；
- 页面内容左对齐，正文行长控制在易读范围；
- 任务详情使用稳定页头和页签，表格承担高密度配置，不把每个字段拆成同形卡片；
- 移动端保证查看和简单预览，SQL 深度编辑以桌面端为主。

## 13. 错误处理

后端将内部错误映射为稳定错误码：

| 错误码 | 页面说明与动作 |
| --- | --- |
| `DATASOURCE_UNAVAILABLE` | 数据源未启用；前往数据源配置 |
| `DATASOURCE_CONNECT_FAILED` | 连接失败；执行健康检测 |
| `SQL_UNSAFE` | SQL 包含不允许的操作；定位编辑器行列 |
| `SQL_COMPILE_FAILED` | SQL 无法在目标数据库解析；显示脱敏数据库消息 |
| `SQL_OBJECT_NOT_FOUND` | 对象不存在或无访问权限；检查库、schema 和授权 |
| `QUERY_TIMEOUT` | 查询超时；缩小条件或优化 SQL |
| `SCHEMA_CHANGED` | 字段结构变化；打开字段差异 |
| `CONFIG_VERSION_CONFLICT` | 配置已更新；重新加载并合并 |

所有错误返回 `requestId`。页面默认展示用户可处理的信息，技术详情折叠显示错误码、请求编号、任务与版本，不显示密码、完整连接串和完整 SQL。

## 14. 迁移与兼容

1. 首先撤销代码或本地配置中的实际密码，更新数据库账号凭据，并恢复由环境变量提供主加密密钥。
2. 创建数据源、密文和 SQL 版本表，不改变现有生产读取路径。
3. 将现有 OA/U8 非敏感配置导入为数据源草稿；密码由管理员重新录入，不从旧配置自动复制到业务表。
4. 将 `material.sql` 导入为物料参照的首个已发布版本，保留原文件读取作为迁移期回退。
5. 使用相同测试参数分别运行旧、新引擎，对比列名、行值、空值、前导零、精度、排序和分页。
6. 切换参照引擎到动态数据源和数据库 SQL 版本，保留一个稳定发布周期的旧读取开关。
7. 更新参照任务页面，再补充销售出库页的链路状态与结构化错误。
8. 稳定期后移除 `sql_resource` 主执行路径和旧启动配置入口。

迁移期间不把模拟查询当作真实业务验收。必须使用实际 SQL Server 版本和只读测试账号完成验证。

## 15. 测试策略

### 15.1 后端自动化

- 数据源配置版本冲突、密文保存和响应脱敏；
- 新连接池失败时旧池继续可用；
- 连接池热切换和旧池回收；
- SQL 允许/拒绝语句矩阵，包括 SQL Server CTE 和方言边界；
- 查询超时、取消、行数、并发限制；
- 草稿与生产隔离、并发发布、历史恢复；
- 字段新增、删除、重名、类型和可空性差异；
- 原始预览与业务预览的参数绑定、精度、NULL、前导零和排序分页；
- 所有异常响应不包含凭据、密文、完整连接串和完整 SQL。

### 15.2 前端自动化

- 权限控制下按钮和敏感字段的可见性；
- 未保存离开提示、版本冲突处理；
- SQL 校验定位和字段差异展示；
- 草稿预览不受任务启用状态阻断；
- 数据源测试阶段反馈；
- 错误码到说明、操作入口的映射；
- 键盘操作、焦点和窄屏查看。

### 15.3 真实环境验收

- UI 修改并启用数据源后，无需重启即可完成连接与查询；
- 数据源错误配置不会中断原活动连接；
- 当前草稿变化不影响生产 Reference API；
- 发布后新请求使用新版本，已开始的请求保持原快照；
- 物料参照新旧结果在真实 U8 测试库中一致；
- OA 插件在版本切换前后仍按现有契约查询；
- 销售出库错误不再显示完整 SQL，并能从页面进入正确诊断入口。

## 16. 分阶段交付

### 阶段 0：安全前置

更换已暴露或进入本地配置的真实凭据，建立主加密密钥、权限和日志脱敏测试。

### 阶段 1：数据源控制面

交付数据表、密文服务、动态注册表、管理 API、数据源页面和运行健康状态。

### 阶段 2：SQL 版本与预览

交付 SQL 草稿、校验器、字段差异、双层预览、发布、恢复和审计。

### 阶段 3：任务工作台

将参照任务大弹窗改为详情页，接入发布就绪状态；丰富销售出库页的链路状态、空状态、错误状态和最近执行。

### 阶段 4：迁移与真实联调

迁移现有资源，执行新旧结果对比，切换生产读取路径，并完成 U8、OA 联调和旧入口退场。

每个阶段独立验收。阶段 1 不要求同时完成在线 SQL；阶段 2 不以阶段 3 的视觉改造作为后端发布前提。

## 17. 完成标准

满足以下条件后，本方案才算完成：

1. 数据源可以从管理端安全维护、检测和热启用，密码不回显且仓库不保存实际凭据。
2. SQL 草稿经过校验、字段检查和双层预览后才能发布，生产运行与草稿完全隔离。
3. 任务可定位到明确的任务、SQL 和数据源版本，变更可审计、可恢复。
4. 参照配置、预览和运行状态在同一任务详情中形成完整操作闭环。
5. 销售出库页空状态有有效信息，异常状态不泄漏完整 SQL，并提供可执行的诊断入口。
6. 自动化测试与真实 SQL Server 对照验收均通过，且不把替身测试表述为真实业务联调。
