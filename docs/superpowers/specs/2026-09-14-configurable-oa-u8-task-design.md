# 可配置 OA 到 U8 任务设计

## 1. 目标

在不改变 OA 插件“调用平台统一接口”这一边界的前提下，平台新增可配置的 OA 到 U8 推单任务。管理员可在任务页面配置读取 OA 数据的 SQL、U8 业务接口和 JSON 请求模板；OA 插件仅提交稳定的 `taskCode`、`masterId`、`formId`、`summaryId`。

新能力与现有参照任务、定时 U8 到 OA 任务共用任务目录、配置发布、执行日志和运行诊断；它们保留各自适合的执行方式。

首期不开放平台直接更新 OA 或 U8 数据库。U8 业务接口返回成功后，平台可以直接提取响应字段，也可以通过受控的只读 SQL 查询 U8 最终落库结果并有限次数轮询。凭证号等结果会被持久化到执行记录，供 OA 插件或人工查询。将来如确认有 OA 业务回填接口，可作为受控后处理器接入；不使用任意 `UPDATE SQL` 作为替代方案。

## 2. 已确认边界

- 平台提供一个统一 OA OpenAPI 受理接口，OA 插件主动调用平台；不新建按任务划分的 OA 对外接口体系。
- `taskCode` 是任务的稳定路由标识，不是流程定义，也不是 OA 表单字段映射。
- U8 token 和账户为共享配置。任务不配置 token 地址、账户、完整主机地址或认证 Header。
- `tradeId`、token 刷新、超时、脱敏、错误标准化由 U8 网关处理，不显示为任务配置步骤。
- OA 到 U8 任务采用单次 U8 业务调用。业务读取可有零到多个顺序执行的命名数据步骤。
- U8 明确成功后允许配置零到多个只读结果查询步骤；它们只能补充或确认 `result.*`，不能修改 OA/U8 数据库。
- 页面允许填写 SQL 和 JSON 模板，但不允许 Groovy、JavaScript、任意 SQL 写入、流程图编排或自定义网络脚本。
- 外部触发请求只接受已约定的四个上下文字段；SQL 可使用任务常量、前序读取结果和 U8 提取结果，不能因此推导为 SQL 只能使用三项 ID。
- 参照任务保持同步查询；OA 到 U8 保持异步执行；现有 U8 到 OA 销售出库任务维持代码管理，首期不强行改造成配置任务。

## 3. 总体结构

```text
OA 插件
  └─ POST /integration/openapi/v1/executions
       └─ ExecutionAcceptor
            └─ TaskDefinitionResolver
                 ├─ 固定任务修订快照、依赖快照和去重键
                 └─ ExecutorRegistry（按任务类型）
                      ├─ REFERENCE_QUERY：同步参照查询执行器
                      ├─ OA_TO_U8：可配置 OA 到 U8 执行器
                      └─ U8_TO_OA：现有代码任务执行器

OA_TO_U8 执行器
  ├─ 只读 SQL 数据步骤（0..n）
  ├─ JSON 模板渲染
  ├─ 共享 U8 网关：token、tradeId、业务接口调用
  ├─ U8 响应结果提取
  ├─ 只读结果查询与有限轮询（0..n）
  ├─ 最小结果集持久化
  └─ 阶段日志、失败分类、断点重试
```

控制面统一，运行时执行器分型。任务目录负责“是什么、当前用哪个版本、是否可运行”；执行器负责“如何运行”。

## 4. 任务与版本模型

新增通用任务目录和不可变修订，而不是为参照、OA 到 U8 分别建设互不兼容的任务管理模型。

### 4.1 `int_integration_task`

稳定字段包括：

- `task_code`、`task_name`；
- `task_type`：`REFERENCE_QUERY`、`OA_TO_U8`、`U8_TO_OA`；
- `enabled`；
- `active_revision_id`、`draft_revision_id`；
- `config_version`；
- 创建、更新和发布审计字段。

代码管理的 U8 到 OA 任务可先登记为 `U8_TO_OA`，但不要求存在可编辑配置修订；任务中心只展示其运行条件和执行情况。

### 4.2 `int_integration_task_revision`

一条修订包含 `task_code`、递增版本号、`DRAFT`/`VALIDATED`/`PUBLISHED`/`ARCHIVED` 状态、`config_json`、校验和、校验摘要、变更说明和审计字段。修订不可修改；编辑总是创建或更新草稿，发布原子切换活动修订。

`config_json` 按 `task_type` 使用受控结构，由后端类型校验器验证。数据源、U8 连接和秘密只保存稳定引用，凭据不进入任务 JSON。

### 4.3 运行快照

受理 OA 请求时解析已发布任务修订，并在执行记录保存：

- `task_revision_id` 和校验和；
- 被引用数据源的活动修订；
- U8 共享连接修订；
- 去重键和触发上下文。

队列等待期间发布新配置不会改变已受理执行的含义。

## 5. OA 到 U8 配置模型

`OA_TO_U8` 修订包含以下区域。

### 5.1 基本信息

任务名称、编码、启用状态、允许的触发来源和非敏感任务常量。任务常量可被 SQL 和 JSON 模板引用，不能保存密码、token 或地址。

### 5.2 数据准备步骤

每个步骤包含：`code`、顺序、只读数据源引用、SQL 正文、命名参数定义、结果基数和输出名。

- SQL 仅允许单条 `SELECT` 或受控的只读查询语句。
- 命名参数通过预编译绑定，禁止字符串拼接和 `${...}` 直接替换。
- 结果基数为 `ONE`、`LIST` 或 `SCALAR`。
- 步骤可使用触发上下文、任务常量和已完成步骤中的标量结果；禁止循环、分支和任意脚本。
- 每个数据步骤在发布前执行 SQL 安全检查、字段检查和样例预览。

变量命名空间为：

```text
trigger.masterId / trigger.formId / trigger.summaryId
task.constants.*
data.<stepCode>.*
u8.response.*
result.*
```

SQL 使用受控的扁平参数别名映射到上述变量，模板和日志展示使用完整命名空间。

### 5.3 U8 业务接口

任务配置业务接口编码或受控相对路径、请求 JSON 模板、成功判断规则、错误消息提取路径和结果输出映射。

第一期默认 `POST application/json`。成功判断和字段提取只支持 JSON Pointer 类路径、HTTP 状态和配置的允许值，不提供表达式语言。发布校验使用脱敏样例上下文渲染模板，检查变量缺失、无效 JSON 和未注册接口。

### 5.4 结果处理与只读后处理

任务首先从 U8 HTTP 响应中提取声明的 `result.*` 输出，例如外部业务号、U8 凭证编号或内部 ID。若业务接口没有直接返回最终凭证信息，可配置零到多个顺序执行的只读结果查询。

每个结果查询包含：

- `code`、顺序和只读数据源引用；
- SQL 正文、命名参数和结果基数；
- 是否必须取得结果；
- `initialDelayMs`、`intervalMs`、`maxAttempts`，均使用平台限制的取值范围；
- 从查询结果写入 `result.*` 的输出映射。

结果查询只能使用 `trigger.*`、`task.constants.*`、`data.*`、`u8.response.*` 和已有 `result.*` 中的标量值。轮询由平台执行器控制，不允许在 SQL 或模板中编写循环。每次尝试都受查询超时和总执行时间限制，并在阶段日志中记录次数、耗时和结果摘要。

若 U8 已明确成功，而必须的结果查询在最大次数后仍未取得结果，执行进入 `PARTIAL_SUCCESS`。后续重试从未完成的结果查询开始，使用已经持久化的 U8 输出，不再次调用 U8 推单接口。

首期后端校验器明确拒绝 `UPDATE`、`INSERT`、`DELETE`、`MERGE`、存储过程调用及其他写入语句，前端也不显示写数据源或写 SQL 配置入口。

未来若确认 OA 提供回填业务接口，可新增 `OA_API_CALLBACK` 后处理器。该处理器同样从已确认 U8 成功的检查点开始执行，不能再次调用 U8 推单接口。

## 6. 统一受理与执行流程

新增统一外部写入入口：

```http
POST /integration/openapi/v1/executions
X-Request-Id: <uuid>
Content-Type: application/json

{
  "taskCode": "OA_EXPENSE_VOUCHER",
  "masterId": "...",
  "formId": "...",
  "summaryId": "..."
}
```

入口只负责请求形状校验、调用方验证、统一响应和关联编号；它内部调用现有 `ExecutionAcceptor`，不另建一套队列或日志体系。响应立即返回 `executionId` 和 `PENDING`，OA 插件通过既有执行详情接口查询最终状态。

受理过程：

1. 校验任务存在、启用、类型可由 OA OpenAPI 触发且全部依赖可用。
2. 获取已发布修订和连接版本快照。
3. 计算固定幂等键。首期 OA 到 U8 默认以 `taskCode + masterId + action` 为同一业务，`force` 仅平台人工操作可用。
4. 创建执行记录和 `RECEIVED` 阶段，发布已有异步执行事件。

运行过程：

1. 加载执行记录中固定的任务修订。
2. 顺序执行只读数据步骤，记录步骤编码、耗时、行数和脱敏摘要。
3. 渲染并保存脱敏后的 U8 请求摘要。
4. 通过共享 U8 网关发送一次业务请求。
5. 确认成功后提取 U8 响应中声明的 `result.*` 输出并立即建立成功检查点。
6. 顺序执行可选的只读结果查询和有限轮询，持续补充 `result.*`。
7. 持久化最终最小结果集并完成执行；结果查询失败时进入 `PARTIAL_SUCCESS`。

## 7. 执行状态、检查点与重试

在已有 `PENDING`、`RUNNING`、`SUCCESS`、`FAILED`、`SKIPPED`、`RESULT_UNKNOWN` 基础上，新增 `PARTIAL_SUCCESS`。它表示目标 U8 已确认成功，但后续回填或查询动作失败。

新增执行检查点和最小结果输出存储：

- `last_completed_stage`；
- `u8_confirmed`；
- `resume_mode`：`FULL` 或 `POST_PROCESS`；
- `result_outputs_json`：任务声明并允许保留的输出；
- 任务、数据源和 U8 连接的版本快照。

规则如下：

| 失败位置 | 状态 | 重试行为 |
| --- | --- | --- |
| U8 调用前 | `FAILED` 且可重试 | 新执行从数据准备开始 |
| U8 网络超时或不确定响应 | `RESULT_UNKNOWN` | 禁止自动和人工盲目重推；先核对 U8 |
| U8 明确失败 | `FAILED` | 按错误类别决定是否允许完整重试 |
| U8 成功、只读结果查询或后续处理失败 | `PARTIAL_SUCCESS` | 仅从失败的结果处理步骤恢复，不再调用 U8 |

首期 `PARTIAL_SUCCESS` 用于 U8 已成功但必须的只读结果查询未完成的真实场景。页面显示已取得的 U8 结果、未完成步骤和“继续结果查询”操作，不提供“重新推单”。

## 8. 现有模块调整

| 现有模块 | 调整 |
| --- | --- |
| `IntegrationExecutionService` | 由任务定义解析器校验和固定修订，不再直接要求每个 `taskCode` 都有 Spring Handler。 |

| `PushPipelineRunner` | 传入修订快照和恢复信息，识别 `PARTIAL_SUCCESS`。 |
| `ReferenceCatalog` / `ReferenceTask` | 迁移到统一任务目录与修订；`sqlResource` 只作迁移输入，不再是生产主路径。 |
| `ReferenceEngine` | 保留参照的分页、筛选和同步语义；抽出底层安全 SQL 执行设施给配置任务复用。 |
| `U8Client` | 演进为共享 U8 网关，实现 token、tradeId、接口调用和统一错误分类。 |
| `ReferenceOpenApiController` | 保留现有参照接口；在同一 `/integration/openapi/v1` 前缀增加统一执行受理入口。 |
| 前端任务页 | 统一任务列表和版本头；参照、OA 到 U8、U8 到 OA 使用类型化详情页。OA 到 U8 页面包含只读结果查询。 |

## 9. 前端信息架构与交互

### 9.1 导航与路由

“任务中心”是任务管理的主入口，参照任务、OA 到 U8 和代码管理的 U8 到 OA 任务都在同一列表展示。原“参照任务”入口在迁移期可以保留为带 `REFERENCE_QUERY` 筛选条件的快捷入口，但不能继续维护另一套任务列表和编辑状态。

首期路由：

```text
/integration/tasks                         统一任务中心
/integration/tasks/create                  新建任务
/integration/tasks/:taskCode               任务详情，按类型显示配置
/integration/execution                     统一执行日志
/integration/execution/:executionId        执行详情
```

数据源、外部连接和定时任务仍使用独立菜单，因为它们是被多个任务引用的资源，不属于某个任务的内嵌配置。

### 9.2 统一任务中心

列表字段包括：任务名称、任务编码、任务类型、触发方式、活动版本、草稿状态、依赖就绪状态、启停状态、最近执行结果和更新时间。支持按名称/编码、类型、启停和就绪状态筛选。

列表操作保持为“进入配置”“调试/预览”“查看执行”。发布、恢复和真实推送只能在任务详情页完成。列表允许在系统没有任何任务时创建第一条任务，不能依赖现有任务作为模板才能新建。

任务类型显示业务化名称：参照查询、OA 推送 U8、U8 推送 OA。任务就绪状态由后端聚合活动修订、数据源、U8 连接和必要配置，前端不自行推断“正常”。

### 9.3 新建任务页

新建任务使用独立页面，不再使用接近全屏的大弹窗。页面先选择任务类型，再在同一页面完成该类型的一期必要配置。`taskCode` 首次保存后不可修改。

所有类型共有字段：任务名称、任务编码、任务类型、允许触发方式和说明。选择 `OA_TO_U8` 后直接显示数据准备、U8 接口和结果处理配置；管理员无需先创建空任务再到另一页面补接口。

新建只保存草稿，不自动启用、不自动发布、不调用 U8。保存成功后地址切换为 `/integration/tasks/:taskCode`，继续编辑同一个草稿。

### 9.4 任务详情框架

详情页顶部固定展示：任务名称和编码、任务类型、活动版本、草稿状态、启停状态、依赖链路和最近一次执行。右侧固定提供“保存草稿”“校验”“发布”，按钮是否可用及阻断原因由服务端返回。

不同任务类型复用页面框架，页签由类型决定：

| 任务类型 | 页签 |
| --- | --- |
| 参照查询 | 基本信息、SQL配置、字段与查询规则、数据预览、版本记录 |
| OA 推送 U8 | 基本信息、数据准备、U8接口、结果处理、调试与发布、版本记录 |
| U8 推送 OA | 基本信息、业务预览、定时配置、依赖状态、执行记录 |

代码管理任务在详情页明确显示“代码管理”，不显示不可编辑的空 SQL 或 JSON 表单。

### 9.5 数据准备页签

数据步骤按顺序显示为紧凑卡片或表格行，通过上移、下移和新增按钮调整，不提供流程图。每个步骤包含：步骤名称、步骤编码、数据源、结果类型、SQL 编辑器、自动识别的参数和预览入口。

SQL 由管理员直接填写，不再选择 classpath SQL 资源。编辑器旁提供“可用变量”面板，可搜索并插入 `trigger.*`、任务常量和前序步骤的标量输出；变量面板只显示当前步骤实际可引用的内容。保存时后端重新解析参数，前端识别结果只用于提示。

每个步骤可单独使用测试上下文预览。页面显示字段名、类型、行数、耗时和脱敏样例，不将预览数据写入任务配置或浏览器持久缓存。

### 9.6 U8 接口页签

页面顶部只读显示共享 U8 连接名称、环境、启用状态和最近认证检测，不显示账户、token、完整认证 URL 或 Header。

可编辑内容包括：业务接口名称、受控接口编码或相对路径、请求 JSON 模板、成功字段路径及允许值、错误消息路径、响应输出映射。首期方法固定为 `POST`、内容类型固定为 `application/json`；固定值直接写在 JSON 模板中，不再增加字段映射表。

JSON 编辑器与数据准备页共用变量面板，支持插入 `trigger.*`、`task.constants.*` 和 `data.*`。编辑器实时检查 JSON 结构，后端校验模板变量、接口白名单和渲染结果。

### 9.7 结果处理页签

页面分为“响应结果提取”和“只读结果查询”两部分。

响应结果提取配置输出名称、JSON 路径、数据类型和是否必填。只读结果查询使用与数据准备一致的 SQL 编辑组件，额外配置首次等待时间、查询间隔、最大次数和输出映射。页面持续提示：该区域只读，U8 推单成功后才执行。

如果接口响应已经返回最终凭证号，任务可以不配置结果查询。若配置了必须取得的结果字段，发布校验要求直接响应提取或结果查询至少能提供该字段。

页面和请求模型中均不存在 `UPDATE`、回填 SQL、写数据源或任意脚本选项。

### 9.8 调试与发布页签

管理员填写测试用 `masterId`、`formId`、`summaryId` 后，可以执行完整的只读准备预览。页面按顺序展示：

1. 每个数据步骤的状态、行数、耗时和结果摘要；
2. 最终渲染的 U8 JSON；
3. 模板缺失变量和类型错误；
4. U8 响应及结果查询规则的静态校验。

默认调试不调用 U8、不执行结果轮询、不移动定时游标、不写入业务系统。若以后增加真实联调按钮，它必须显式标注目标环境、二次确认并创建正式执行记录，不能复用普通预览接口。

发布区显示服务端返回的检查清单：SQL安全、参数完整、字段结构、JSON可渲染、U8接口有效、结果输出完整和依赖健康。任何阻断项都提供定位到对应页签的入口。

### 9.9 版本、离开保护与错误状态

版本记录展示发布号、发布人、时间、说明、校验和和配置摘要；恢复历史版本只生成新草稿，不直接替换生产版本。

未保存修改离开页面时确认；已经保存的草稿可直接离开。并发保存冲突提示重新加载和复制当前编辑内容，不静默覆盖。SQL、JSON和测试参数不写入 `localStorage` 或 `sessionStorage`。

错误信息优先展示任务、步骤、稳定错误码、请求编号和可执行动作。数据库异常不返回完整 SQL，U8异常不返回 token、账户或未脱敏响应。

## 10. 安全与运行约束

- SQL 编辑、预览、生产执行全部在后端；浏览器永不获得 JDBC 完整连接信息或密码。
- 读取数据源维持数据库侧只读账户和事务约束。
- U8 账户和 token 不进任务 JSON、执行列表、浏览器存储或普通日志。
- 对外写入接口采用统一的调用方验证策略、`X-Request-Id`、请求体限制和脱敏审计。当前参照接口的临时匿名状态不能原样用于 U8 写入接口；实际认证机制遵循部署的 OA 插件接入策略。
- 任务接口不能配置任意外部主机、Header 或认证信息。
- 执行日志保存版本、阶段、行数、错误码和允许保留的结果输出；大批量原始查询结果和敏感请求响应只保存脱敏、截断摘要。

## 11. 分阶段实施

### 阶段 A：统一任务控制面和参照迁移基础

建立任务目录、修订、发布和运行快照；将参照 SQL 从 classpath 资源迁移为页面编辑、数据库保存和发布执行。保留旧资源作为一次性迁移源和短期回退开关。

### 阶段 B：共享 SQL 与 U8 网关

抽取只读命名 SQL 执行设施；实现共享 U8 token、tradeId、HTTP 调用和错误分类。只读 SQL 设施同时服务数据准备和 U8 成功后的结果查询。此阶段不暴露新的 OA 推单接口。

### 阶段 C：可配置 OA 到 U8 执行器和统一受理

实现 `OA_TO_U8` 配置校验、异步执行器、统一 OpenAPI 入口、响应提取、只读结果查询、执行结果输出和重试检查点。前端完成统一任务中心、独立新建/详情页、任务配置与只读调试预览。

### 阶段 D：任务工作台、迁移与验收

合并任务列表和执行诊断，迁移一个真实审核推单任务与一个费用凭证推送任务，完成 SQL 预览、U8 沙箱推送、幂等、结果未知和配置版本切换验收。

OA 自动回填属于阶段 D 之后的独立增量：仅在 OA 提供明确业务 API、认证方式和幂等规则后实现 `OA_API_CALLBACK`。现有 `configuration-console-b-reference` 和 `configuration-console-c-workbench` 实施计划基于较早的参照专用模型，不能原样执行；新的实施计划必须以本设计的统一任务修订和类型化前端为准，复用其中仍成立的 SQL 安全、数据源、预览和迁移任务。

## 12. 验收标准

1. 管理员能在页面创建、校验、预览、发布和停用参照与 OA 到 U8 任务；编辑草稿不会影响活动执行。
2. 参照生产 SQL 不再依赖 SQL 资源文件，运行日志可定位任务、SQL 修订和数据源修订。
3. OA 插件通过一个统一平台接口受理 OA 到 U8 请求，重复请求不会重复创建 U8 单据。
4. 任意数量的配置型 OA 到 U8 任务由同一个执行器处理，不为每个任务新增 Spring Handler。
5. token、tradeId 和账户配置不要求任务重复配置，并且不会泄露到浏览器或日志。
6. 接口直接返回凭证号和推单后只读查询凭证号两种任务都可以配置，无需新增 Handler。
7. 失败前、结果未知、U8成功后结果查询失败三类场景具有不同且安全的重试行为。
8. 首期不存在直接写 OA/U8 数据库的接口、SQL 配置、前端选项或数据源权限。
9. 统一任务中心可从空系统新建任务；OA 到 U8 新建页能够配置 SQL、U8 接口、结果提取和只读结果查询。
10. 参照同步查询和现有定时 U8 到 OA 任务功能回归通过。
